# План

Каждый пункт с кодом — отдельная ветка и PR: зелёный CI и ИИ-ревью перед слиянием.
Мелкие осмысленные коммиты в формате Conventional Commits (`feat:`, `fix:`, `test:`, `docs:`, `ci:`).
CI появляется в первом же PR своей части, поэтому все следующие изменения проходят автопроверки.

| # | PR | Что внутри | Требования |
|---|---|---|---|
| 1 | `docs: requirements, decisions, api` (первый коммит в `main`) | Документация, `CLAUDE.md`, `data/trips.json`, `Makefile` | R11 |
| 2 | `feat(backend): summary` | Каркас бэкенда, `summarize()` и тесты; **CI бэкенда**: ruff, mypy, import-linter, pytest на Postgres через testcontainers | R2, R9, X2 |
| 3 | `feat(backend): days endpoint` | Схема, загрузка `trips.json`, границы дня, `GET /days/{date}` | R1, R2, R11 |
| 4 | `feat(backend): create trip` | `POST /trips`, проверка данных, `ON CONFLICT`, тест 20 одновременных запросов | R5–R8, R10, X5 |
| 5 | `feat: docker compose` | API и Postgres одной командой, `make up` | X1 |
| 6 | `feat(app): core` | Каркас Flutter, `Result` / `Failure`, Dio, DI, адрес API из `env/*.json` (D12), время в Алматы, тема Material 3 (светлая и тёмная), smoke-тест DI; **CI клиента**: format, analyze, тесты, свежесть генерации | X2, X3, X7 |
| 7 | `feat(app): day screen` | `DayBloc`, сводка, список, переключение дней, состояния загрузки / пустого дня / ошибки | R3, R4, X7 |
| 8 | `feat(app): add trip` | `AddTripBloc`, форма, адаптивный выбор даты и времени, повтор с тем же `id`, тест фичи целиком | R5, X6, X7 |
| 9 | `feat: deploy backend` | Бэкенд на хостинге с HTTPS, `env/prod.json` с его адресом (D12) | X8 |
| 10 | `ci: release apk` | Сборка APK с `env/prod.json` и публикация в GitHub Releases | X4 |
| 11 | `docs: readme` | Запуск, таблица требований, скриншоты с симулятора iOS, журнал ИИ | D2–D4 |
| 12 | `feat(app): redesign the day screen and the trip form` | Редизайн экрана дня и формы по макетам Claude Design (`docs/design/`), D11 | X7 |
| 13 | `feat(app): swipe days like tabs and drag the trip sheet down` | Дни листаются как вкладки, лист формы смахивается вниз (замечания пользователя после редизайна) | X7 |
| 16 | `feat(app): day screen fixes` | Экран дня переживает холодный старт бэкенда на Render: строка «Сервер просыпается», сам повторяет загрузку до 90 с (D12); сводка начинается с «На руки», наличные и карта под «Выручкой»; при крупном тексте «Перейти к сегодня» — кнопка (D11) | R3, R4, X7, X8 |

Бэкенд (2–5) и клиент (6–8) не зависят друг от друга: их можно вести параллельно в разных
сессиях. Деплой (9) идёт после `docker compose` (5), сборка APK (10) — после деплоя. Клиент до готовности бэкенда работает с фейковым репозиторием и контрактом
из [api.md](api.md).

Перед PR 7 — по желанию час на набросок экрана дня, формы и состояний в рамках Material 3.
Выбранный вариант кратко записывается в раздел «Интерфейс» в [architecture.md](architecture.md).

## Готово, когда

- [ ] `docker compose up` на чистой машине поднимает API с данными из `trips.json`
- [ ] Приложение на телефоне показывает 01.10.2026 со сводкой 2 / 3 900 / 585 / 3 315 / 1 500 / 2 400
- [ ] Остальные дни совпадают с таблицей в [data/README.md](../data/README.md)
- [ ] Добавленная поездка появляется в нужном дне; повторная отправка не создаёт дубль
- [ ] Экран дня и форма работают в тёмной теме и при масштабе шрифта 200%
- [ ] CI зелёный на `main`, APK лежит в Releases
- [ ] APK из Releases на телефоне вне домашней сети показывает сводку за 01.10.2026
- [ ] В README у каждого требования есть ссылка на код и тест
- [ ] `docs/ai-log.md` заполнен реальными случаями со ссылками на коммиты
